# Opera 3 snapshot tooling

## `scripts/snapshot_opera3.py`

Captures an Opera 3 (FoxPro) installation's schema + sample data into a
JSON file with the same shape as `scripts/opera_snapshot.json` (which is
the SE snapshot, generated by `scripts/snapshot_opera.py`).

The two scripts live side-by-side in `scripts/`:

| Script | Engine | Connection |
|---|---|---|
| `scripts/snapshot_opera.py` | SQL Server (Opera SE) | pyodbc + INFORMATION_SCHEMA |
| `scripts/snapshot_opera3.py` | FoxPro DBF (Opera 3) | dbfread via `Opera3Reader` |

Output JSON shape is identical so the two can be diffed directly. The
SE script is ignored by `.gitignore` (it has hard-coded MSSQL credentials
embedded); the Opera 3 script is committed because it takes the data
path as an argument and has no embedded secrets.

### Why we need this

75% of Opera users run **Opera 3**, not Opera SE. The SAM rewrite must
hit 100% Opera 3 compatibility. Today the TS port has been written
against the SE schema only — we don't yet know which queries break
against Opera 3 because nobody has compared the schemas side by side.

The diff between the two snapshots is the **concrete punch list** of
tables and columns that need version-specific handling.

### Prerequisites

- Python 3.9+
- `dbfread` package (`pip install dbfread`)
- Read access to the Opera 3 data folder. If accessed over SMB, mount
  the share first or use the `sql_rag.smb_access` helper.
- Run from the project root so `sql_rag.opera3_foxpro` imports cleanly.

### Capture

```bash
# Local Opera 3 install
python scripts/snapshot_opera3.py /path/to/opera3/data

# Default output: scripts/opera3_snapshot.json
# scripts/ is git-ignored so the snapshot stays local with the customer
# data inside it.
```

For a Windows host running Opera 3 directly:

```powershell
python scripts\snapshot_opera3.py "C:\Apps\O3 Server VFP"
```

### Compare against SE

Both snapshots share the same JSON shape, so a deep diff highlights
table and column differences:

```bash
diff <(jq -S 'del(.timestamp) | del(.data_path) | del(.engine)' scripts/opera_snapshot.json) \
     <(jq -S 'del(.timestamp) | del(.data_path) | del(.engine)' scripts/opera3_snapshot.json) | less
```

A focused field-presence diff:

```bash
jq -r '.tables | to_entries[] | "\(.key)\t\(.value.columns | length)"' scripts/opera_snapshot.json | sort > /tmp/se-tables.tsv
jq -r '.tables | to_entries[] | "\(.key)\t\(.value.columns | length)"' scripts/opera3_snapshot.json | sort > /tmp/o3-tables.tsv
diff /tmp/se-tables.tsv /tmp/o3-tables.tsv
```

### Centralise the schema reference

Once captured, push to the central knowledge base so other developers
can consult it (per the CLAUDE.md mandate that Opera knowledge live
in `~/opera-knowledge-ref/packages/opera-knowledge/`):

```bash
# Strip sample customer records before publishing — only schema is
# generally appropriate to commit centrally.
jq '.tables |= map_values({columns, field_types, count, key_field, last_modified})' \
   scripts/opera3_snapshot.json \
   > ~/opera-knowledge-ref/packages/opera-knowledge/schema/opera3_snapshot.json

cd ~/opera-knowledge-ref
git pull
git add packages/opera-knowledge/schema/opera3_snapshot.json
git commit -m "schema: opera3 snapshot from <site/install name>"
git push
```

### Use the diff to audit existing TS code

Once the diff is in hand, the SAM rewrite TS code needs an audit pass
against any tables/columns that differ:

1. Grep the TS `apps-sam/*/src/services/` tree for table names that
   appear in the diff (e.g. `pname`, `stran`, `nbank`, `aentry`).
2. For each call site, check whether the columns referenced exist in
   both snapshots. If not, the query needs a version-specific path:

```ts
if (ctx.operaType === 'opera-3') {
  // Opera-3-specific query
} else {
  // SE query
}
```

3. Add a regression test that exercises the version-specific branch.

Most queries should "just work" because Pegasus has kept the table and
column names stable across versions. The expected delta is small —
a handful of newer SE-only columns (e.g. recent GoCardless integration
fields) and possibly type-coercion differences.
